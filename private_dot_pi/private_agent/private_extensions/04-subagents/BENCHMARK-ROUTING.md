# Benchmark routing

Automatic subagent model selection is local and deterministic. It never calls an LLM or network service. An explicit agent `model:` always wins; without one, Pi attempts benchmark routing and otherwise starts the child without `--model` so its configured default is used. Explicit `thinking:` always wins.

## Catalog synchronization

After enabling models with `/scoped-models` and saving with Ctrl+S, `/catalog sync` resolves metadata and pricing for enabled custom and native `/login` models. Missing Artificial Analysis identities are reviewed interactively as a complete generic or thinking-specific batch; generic and specific mappings never coexist. Discovery and publication run through the in-process TypeScript AA service, propagate cancellation, and keep baseline replacement under one writer lock.

The sync report lists **benchmark-qualified** profiles per AA variant using the same capability, required-dimension, floor, faithfulness, and coverage gates as routing. This does not imply runtime eligibility: run `/model-health` to record fresh latency/throughput, then `/reload` (or start a new session) so routing loads new mappings and combines benchmark qualification with health.

## Snapshot lifecycle

Snapshots live at `assets/aa/manifest.json` and `assets/aa/models/<opaque-id>.json`. Directories must be mode 0700 and plaintext files mode 0600; content and manifest SHA-256 digests are verified at load. No real scores or identity mappings are invented. The loader rejects missing, duplicate, ambiguous, future-dated, malformed, stale-manifest, or methodologically incompatible snapshots. Schema v4 identity is exact `provider/model/thinkingLevel`, where `thinkingLevel` is `null`, `off`, `low`, `medium`, `high`, `xhigh`, or `max`; v3 and earlier manifests are rejected by the normal loader and `node agent/extensions/09-catalog/aa/cli.ts --check`. Every v4 snapshot also records the canonical public-page URL, retrieval time, raw-content and canonical-currentModel SHA-256 digests, extractor version, and pinned public Intelligence Index methodology version (currently 4.1.1). A model may have either one generic (`null`) record or specific variants, never both; there is no fuzzy runtime matching. The same reviewed AA model may map to multiple Pi providers because local Health measurements remain provider-specific.

Prefer `/catalog sync` to identify missing mappings and review them interactively. For direct maintenance, `node agent/extensions/09-catalog/aa/cli.ts --missing` lists enabled models needing reviewed mappings. `node agent/extensions/09-catalog/aa/cli.ts --discover provider/model` queries the documented `/api/v2/language/models` catalog and prints suggestions only; it never accepts one. Free-tier users can explicitly select the reduced catalog with `PI_AA_API_URL=https://artificialanalysis.ai/api/v2/language/models/free`. Supply a reviewed exact stable ID with `node agent/extensions/09-catalog/aa/cli.ts --add provider/model --aa-model-id ID` (optionally `--thinking-level low`, etc.); add remains generic by default. For reviewed migrations use `node agent/extensions/09-catalog/aa/cli.ts --replace-batch FILE`, where FILE is a strict JSON array of `{provider,model,thinkingLevel,aaModelId}` mappings. It fetches the catalog once, validates the complete batch, stages every snapshot, and replaces the manifest last. `node agent/extensions/09-catalog/aa/cli.ts --check` validates local files without network access. `node agent/extensions/09-catalog/aa/cli.ts --refresh provider/model` refreshes every current variant for that model with one catalog fetch. Refresh weekly, manually after methodology changes, or immediately after adding models. Pi startup, `/reload`, and subagent routing never query AA.

A strict mapping-only v3 migration is available only through `node agent/extensions/09-catalog/aa/cli.ts --refresh-all`: it extracts only reviewed identity mappings, stages every freshly fetched v4 record, publishes the v4 manifest last, and cleans old files only after publication. Writers install immutable files exclusively and roll back files created by the transaction if failure or cancellation occurs before manifest rename. Manifest rename commits the transaction; later pruning failures are cleanup warnings and never roll back or misreport that commit. A failed pre-commit migration leaves the v3 manifest usable for retry (though runtime intentionally rejects it).

The direct TypeScript refresh service reads `artificialAnalysis.apiKey` from mode-0600 `agent/credentials.json` (`AA_API_KEY` may override it) and uses `x-api-key` only for an authenticated request to an allow-listed canonical HTTPS full/free catalog endpoint. Catalog redirects are rejected. Bodies are streamed under configured byte caps while timeout and caller cancellation remain active. Each snapshot-producing command (`--add`, `--replace-batch`, `--refresh`, and `--refresh-all`) separately constructs only the canonical HTTPS `https://artificialanalysis.ai/models/<exact-catalog-slug>` request, with no API or authorization header. Every public redirect hop is manually validated, size and hop counts are bounded, the final URL must equal the original canonical URL, and the configurable rate delay is abortable (`PI_AA_PUBLIC_PAGE_DELAY`, zero for deterministic tests). It narrowly extracts exactly one Next/RSC `currentModel`; its UUID, slug, and displayed name must byte-match the reviewed catalog record. The API remains authoritative for identity and every non-null value. Public raw evaluation components fill API nulls only. Corresponding non-null raw components must agree after unit normalization within 0.001; the rounded API Intelligence and Agentic composites use a 0.51-point tolerance. Any larger conflict aborts the staged transaction. This public-page supplementation is refresh-time only: startup, reload, check, missing, model selection, and routing remain network-free (discover retains its catalog query). The documented fields map as follows:

- The API supplies the Coding index exclusively. API Intelligence and Agentic composites remain authoritative when present.
- Missing raw Intelligence and Agentic values can be filled from `currentModel.intelligenceIndex` and `.agenticIndex`.
- Tool Use stores auditable raw component records for τ³ Banking (`tauBanking`; public-page field availability is limited to the current AA page representation), normalized GDPval-AA (`gdpvalNormalized`), and legacy τ² Telecom (`tau2`). Each records its normalized value, source kind/field/URL, benchmark id/version/status, retrieval time, and source-record digest. Its strict v1 derivation uses the mean of τ³ Banking and GDPval-AA only when both exist; otherwise it uses τ² Telecom alone; otherwise it is unavailable. It never uses a lone primary component or mixes τ² with the primary pair.
- Scientific Reasoning combines HLE, GPQA, and CritPt (`hle`, `gpqa`, `critpt`).
- Long Context, Instruction Following, Knowledge, and Faithfulness use `lcr`, `ifbench`, `omniscienceBreakdown.accuracy`, and `1 - omniscienceBreakdown.hallucinationRate` respectively.
- Public Intelligence output-token and execution-time figures are not substituted for profile-specific output-token metrics or Coding Agent time.

The local composite definitions are unchanged. API composite methodology remains 4.1; public raw components supplement the reduced API snapshot and carry the separately pinned public-page methodology provenance.

Composite component dimensions are available only when every documented component is present. Missing values remain null. The free `/language/models/free` catalog exposes only the Intelligence, Coding, and Agentic indices; official public-page supplementation can make an exact snapshot eligible when all remaining raw components are present and verified. Models whose public page still lacks a required component remain ineligible. The current language-model API and public model page do not provide profile-specific Output Tokens per Task or Coding Agent execution time, so snapshots preserve those fields as unavailable. Routing uses a visible code-owned per-profile output-token fallback until AA exposes a supported per-task value; diagnostics state whether AA or the fallback supplied it. Public-page extraction is used only while explicitly publishing snapshots; it is never used at runtime.

## Decision rule

Schema-v4 `routing-policy.json` version-controls fixed score anchors, profile weights, required dimensions, profile-weighted coverage floors, non-faithfulness mandatory floors, functional text/context/output constraints, output-token metric/fallback, absolute quality tolerance, and default thinking effort. A single global `faithfulnessPolicy` applies AA Omniscience non-hallucination rate × 100 at 7.5 to research and review without model/provider exemptions; profile faithfulness floors are invalid. These are initial code-owned routing policy values and must be recalibrated when representative routing evidence is available. Scores are normalized against fixed anchors, not the current candidates.

For positive-weight dimensions quality is `Q = sum(available weight × normalized score) / sum(all weight)`. Diagnostics also expose available-only quality `A`, profile-weighted coverage `C`, total/available weight, and missing/available weighted dimensions. Required dimensions must be present and `C` must meet the profile floor; null is never imputed. Each candidate diagnostics record has ordered rejection reasons even when no model wins. Benchmark gates distinguish missing required dimensions, non-faithfulness mandatory floors, the global faithfulness floor, minimum coverage, and invalid benchmark data. Models with unknown text-input capability, an exact snapshot variant mismatch, unhealthy chat status, or non-positive fresh local latency/TPS are ineligible. A verified configured model with no declared input list normalizes to its text-chat default; an unknown enabled ID never receives that default. For reasoning models routing uses explicit frontmatter `thinking:` when supplied, otherwise the profile default, and mirrors Pi's clamp: standard `off` through `high` are supported unless mapped to `null`, while `xhigh` and `max` require non-null mappings; unsupported requests scan upward, then downward. A `null` mapping is never treated as an AA wire value, so benchmark lookup uses the clamped Pi level (with `minimal` as `low`) unless a non-null provider value is itself a canonical AA level. It requires that exact variant when variants exist. Generic-only mappings represent a fixed endpoint behavior and remain eligible independent of requested effort. When provider compatibility says reasoning effort is not selectable, automatic routing omits the child `--thinking` argument; validation rejects specific effort mappings for that provider. Explicit agent `thinking:` remains authoritative. Controllable non-reasoning models use `off`; diagnostics record the selected `benchmarkThinkingLevel`. Pareto elimination considers both task quality and predicted local completion time; a faster candidate is not removed merely because another model has higher quality. The router then keeps candidates within an absolute tolerance of the best normalized task quality and selects the quickest by `latencyMs + 1000 * expected output tokens / tokensPerSecond`. AA benchmark/harness time is a later tie-breaker only and never replaces local latency. Profile-weighted coverage is the preceding tie-break; the final identity comparison is explicit code-point lexical order, never locale-sensitive.

Health probes use a short eight-token request, so latency/TPS are local estimates rather than statistically complete endpoint measurements. `reasoning`, `input`, context/output limits, and thinking-level maps are functional routing metadata. Names, family/tier words, parameters, active parameters, and quantization are never routing signals. AA records are mapped only to exact callable Pi identities: the configured fixed-effort Gemma/GLM endpoints retain one manually reviewed generic snapshot, but their alternate non-reasoning AA variants cannot be aliased to those same Pi IDs, Gemma/GLM non-reasoning variants cannot be aliased to their generic configured IDs when their providers cannot invoke reasoning effort, and Laguna has no exact reviewed record. Pi supports `max` distinctly from `xhigh`, so GPT-5.6 `max` records use exact `max` mappings rather than aliases. Non-callable or non-exact public variants intentionally remain unmapped.
