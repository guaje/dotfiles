# Dynamic model catalog

## BenchLM benchmark archive

`/catalog sync` refreshes the reviewed BenchLM archive used by delegation routing. Runtime routing never uses the network. Runtime IDs join only through reviewed rows in `../04-subagents/assets/benchlm-mappings.json`: a reviewed row is authoritative, and an unreviewed endpoint may resolve only by strict exact-slug matching against BenchLM's own identity. Artificial Analysis bindings remain reviewed-mapping-only. Publication retains only enabled, mapped models, uses strict HTTPS, bounded payloads and retry backoff, and atomically publishes nothing on failure. Every sync re-captures BenchLM and every model file then takes a content comparison: it is rewritten only when BenchLM's published figures, ranks, rows or methodology moved, or when the set of endpoints sharing that model changed. `capturedAt` and `sourceSnapshotId` are capture provenance, not evidence, so an upstream re-publish of identical data rewrites no model file; the manifest's `generatedAt` still records when the generation was last verified upstream, which is what the staleness gate reads. Methodology or feed-membership changes stop publication for review. Snapshots retain category scores, detail verification status, source snapshot ID, attribution, and the CC BY-NC 4.0 license.


`/scoped-models` is also the deletion authority: every sync drops manifest entries for models nobody enables and reclaims their files under `models/`. A composite the Artificial Analysis manifest still references is not deleted by the BenchLM pass, because that block is not BenchLM's to delete alone: only its BenchLM block is cleared, and the same sync's AA pass then drops its own entries (`enforceScope`) while its final cleanup removes the file. An AA reference therefore defers deletion by the rest of one sync, never indefinitely — a de-scoped model never keeps a file just because AA evidence exists — and once AA has released the file the BenchLM pass queues the deletion itself. Composites with no remaining publisher are queued to the tracked-asset cleanup, which runs `chezmoi forget` and `rm -f` inside `04-subagents/assets/` only. An unread (empty) scope removes nothing.

`09-catalog` keeps `agent/models.json` provider-only. Its awaited extension factory restores validated owner-only catalog state, refreshes stale custom-provider inventories, and registers available chat models before Pi resolves model scope.

## Commands

- `/catalog` — show inventory, scope, pricing, freshness, missing registrations, and unresolved active prices.
- `/catalog refresh` — refresh custom providers while retaining enabled omissions through temporary discovery failures, then show the unified overview.
- `/catalog sync` — reconcile settings, resolve prices, and interactively review complete Artificial Analysis variant sets for enabled custom and native `/login` models.
- Artificial Analysis CLI: `node agent/extensions/09-catalog/aa/cli.ts --check|--missing`, `--discover provider/model`, `--add provider/model --aa-model-id ID [--thinking-level LEVEL]`, `--replace-batch FILE`, `--refresh provider/model|--refresh-all`, `--methodology|--methodology-diff`, or `--health`.

`/catalog sync` is interactive because AA UUIDs and thinking levels require review. Discovery and publication call the TypeScript AA service in-process and receive `ctx.signal`; no shell process or temporary batch file is involved. Publication resolves runtime aliases under the writer lock and writes snapshots under the canonical identity, so legacy runtime-identity snapshots remain manageable. The separately reviewed canonical mapping file is never rewritten implicitly. Every shared AA write validates the complete resulting batch and the final canonical pins. A mapping for a model that is no longer enabled may survive a transaction only when its provider, model, thinking level (including generic `null`), and AA UUID exactly match the existing v4 manifest or migrated v3 baseline; new or modified disabled mappings are rejected. Direct CLI writes therefore never drop out-of-scope mappings implicitly; `/catalog sync` scope enforcement is the only lifecycle trimmer.

Runtime state and reports allow-list model metadata and never persist API keys, headers, OAuth data, or resolved provider authentication. Provider-supplied `reasoning` and explicit `thinkingLevelMap`/`thinking_level_map` values are validated, persisted, and registered verbatim; an explicit provider map has provenance and wins over both LiteLLM effort metadata and an AA-reviewed fallback. In any supported metadata root, including `model_info` and `litellm_model_info`, LiteLLM may provide `supports_reasoning` plus an explicit Pi `thinking_level_map`, `supported_reasoning_efforts` (or camelCase, or LiteLLM's own `reasoning_effort_levels`), or individual `supports_<level>_reasoning_effort` booleans. Input modalities come from `input`/`input_modalities`/`modalities` arrays (kept in Pi's text-and-image vocabulary), `capabilities.vision`, or `supports_vision`. Precedence is explicit map, complete effort list, then per-level flags. A reasoning-effort list must be non-empty, unique, and contain only `none`, `off`, `minimal`, `low`, `medium`, `high`, `xhigh`, or `max`; malformed lists and flags are ignored. Explicit maps and valid complete effort lists derive provider-provenance Pi maps. Individual LiteLLM flags derive only lower-priority `provider-inferred` evidence because absent flags do not prove a level is unsupported: they conservatively expose advertised values, but a complete AA-reviewed map is retained over them. Explicit provider maps or lists still win over reviewed state. Explicit `none`/`off` supplies the exact off wire value, otherwise off is `null`; gaps clamp upward and then to the highest positively advertised effort, including Pi `xhigh` and `max`.

Capability declarations are honoured in both directions but only when actually declared: `supports_vision: false` declares that this route cannot take images, while LiteLLM's `null` placeholders for unset capability metadata (including `reasoning_effort_levels`) stay unknown and never deny a capability another source evidenced. Because provider evidence outranks every other source, a gateway that declares its own modalities and effort levels becomes the authority for those models and the reviewed-AA and authoritative lookups degrade to fallbacks.

A custom provider that explicitly supports effort selection can be reviewed at specific levels even when its inventory omitted `reasoning`. Variable-effort models offer only the exact benchmark levels `off`, `low`, `medium`, `high`, `xhigh`, and `max`; fixed-effort models offer only a generic mapping. An existing generic AA mapping is preserved during interactive sync; converting it to specific variants requires a separately reviewed `canonical-mappings.json` change before candidate review. After a complete thinking-specific review, the catalog persists and registers `reasoning: true`; when `off` was reviewed alongside reasoning levels it persists as `off: null`, because an AA off snapshot does not establish a provider wire value. `minimal` maps to the lowest reviewed reasoning level, exact reviewed levels stay exact, and unreviewed higher requests clamp to the next reviewed (or highest) level. Choosing Cancel review aborts that model's review, and incomplete reviews never publish.

Model capabilities are resolved per field from the strongest available declaration, never from a name. What this exact route declares in `/models` or `/model/info` wins, then the reviewed AA snapshot published for that runtime identity (`capabilities` recorded from the same exact-UUID public page record), then the authoritative public catalog entry for the same model identity. Only affirmative declarations count: an authoritative record that documents reasoning support sets `reasoning: true`, while a missing or negative authoritative declaration never sets `reasoning: false`, because a route may accept effort parameters the public catalog does not advertise. Pi reads `input` for the image affordance and `reasoning` for the thinking selector, so an inventory that annotates nothing is *unknown*, not text-only; `input` then falls back to Pi's text-chat default and records no provenance. Whichever set supplied the strongest claim is persisted as `capabilitiesProvenance` (`provider-inventory`, `aa-review`, `authoritative`, or `last-known-good`), the last-known-good merge carries an evidenced set forward when a later inventory stops annotating it, and `/catalog sync` prints the modalities, reasoning state, and declaring source for every scoped model. A mapping published during a sync contributes its capability evidence from the next `/catalog refresh`, which pi also performs at startup. A reviewed thinking-level set is still only registered as a Pi effort selector when the provider declares reasoning-effort support; when it does not, sync says so instead of silently dropping the reviewed evidence.

`/catalog sync`, CLI discovery, and publication use the authenticated AA **free** endpoint (`/api/v2/language/models/free`). Sync fetches it once, reuses that exact catalog for every confirmed reviewed publication, and then scrapes each selected canonical public page to supplement only null API metrics. Suggestions (separator-normalized base, reasoning variants, and one stripped quantization suffix such as `-nvfp4` for self-hosted variants) never alter mappings. When Artificial Analysis changes its Intelligence Index methodology, discovery and publication fail closed with an error naming both the local pin and the upstream (or on-disk artifacts) version, which `/catalog sync` surfaces as an AA-unavailable warning; a digest-verified manifest pinned to a previous methodology is republished wholesale under the current pin by the next `--refresh-all` or interactive publication, preserving the mapping set while never trusting old snapshots across methodology versions. Pricing resolves consistently for every provider: provider/catalog/runtime, exact OpenRouter then a unique normalized suffix, explicit numeric Ollama Cloud rate, reviewed override, then AA catalog reference prices—first an exact normalized identity, then a quantization variant inheriting its base model's price (one raw `-<quant>` suffix such as `-nvfp4` stripped, unique base required). Ollama Cloud and the AA price catalog are each loaded lazily once only after a model remains unresolved; an AA fetch failure silently degrades to unknown, availability without a numeric rate neither implies free nor suppresses another source, and is `price-unpublished` only if no rate remains. The sync then persists every price it resolved for scoped custom models into catalog state—filling gaps only, never overwriting a provider-published state cost—so `/catalog`, `/catalog refresh`, and catalog health report the same enrichment the sync report shows, and later refreshes preserve the filled costs through the last-known-good merge. Persisted `authoritative:`, `ollama-cloud:`, `reviewed-override`, and `aa-catalog:` costs are re-resolved from their live sources on every sync instead of being reused as provider-catalog prices.

After the interactive review loop, `/catalog sync` enforces `/scoped-models` (`enabledModels` in the AA runtime settings) as the single lifecycle authority for the reviewed-AA asset folder: under the writer lock it drops manifest entries and canonical-mapping rows whose runtime and canonical identities are all no longer enabled — entries kept under a canonical identity survive while their scoped runtime still resolves to it — rewriting the manifest and `canonical-mappings.json` in place without re-fetching retained snapshots. Missing, corrupt, or legacy-pinned manifests fail enforcement closed as a skipped-enforcement warning. This enforcement rewrite counts as a changed AA generation, so a de-scoped model is cleaned up and reported even in a sync with no publications. Only after the whole `/catalog sync` succeeds, including final catalog reconciliation, does the decisive reviewed-AA cleanup run — when scope enforcement changed the generation or at least one successful publication reports `changed: true`. A fully no-op sync skips that cleanup. It is lock-serialized and removes secure generated snapshots not referenced by the final manifest. Interactive publications defer the normal writer prune so an outer sync failure cannot remove an earlier generation. Direct AA CLI add/replace/refresh paths retain their existing grace-period per-write prune. Cleanup never invokes chezmoi. When an AA generation changed, the final notification lists deterministic net artifacts: `M` for changed manifest, mapping, or benchmark-health content (manifest first, mappings second, benchmark health third), `A models/<snapshot>` for final manifest additions, and `D models/<snapshot>` for generated files removed by final cleanup. Display paths are relative only when the target is actually inside `PI_AA_SNAPSHOT_ROOT`; a custom `PI_AA_CANONICAL_MAPPINGS` target outside that root is shown as its absolute path.

After a nonempty M/A/D list, the notification prints copy/paste-ready POSIX command groups in order: `chezmoi add --` for absolute M/A targets, then `chezmoi forget --` and `rm -f --` for absolute D targets. Empty groups are omitted. Every argument is POSIX single-quoted (an embedded `'` is encoded as `'"'"'`), so the output contains no shell expansions, and it never derives or prints a chezmoi source path. A long argument is emitted as short adjacent quoted fragments joined by an escaped newline; continuation fragments begin at column zero so POSIX concatenates the exact original pathname. Copy each entire group unchanged rather than retyping a visibly wrapped filename. The commands are guidance only: sync does not execute chezmoi or `rm`, so it cannot know which deleted paths chezmoi currently manages; run `chezmoi forget` only for deletions identified as tracked by `chezmoi status`. Cleanup has already removed D files before rendering, so the printed `rm -f` is deliberately redundant and idempotent while still making the requested working-tree deletion explicit. If any target is nonabsolute or contains a C0/DEL control character, all exact command groups are suppressed and only a generic warning is shown without echoing the unsafe target. That net report assumes no concurrent external AA writer during interactive review. It also prints cleanup/capture/publication warnings, any `Removed out-of-scope AA mappings` list, and keeps `Review with: chezmoi status` after the command groups only when changes were captured; it does not run it.

Readers tolerate the publication/cleanup handoff with one bounded retry only if a referenced snapshot disappears and a re-read proves that the manifest content switched. Missing snapshots with an unchanged manifest, corruption, and unsafe permissions still fail closed.

After scope enforcement, `/catalog sync` assesses upstream benchmark coverage at most weekly: unless a parsable `assets/benchmark-health.json` is younger than seven days, the service samples the newest dated base-release model pages and classifies each monitored sub-benchmark field as `active`, `lagging`, `retired`, or `unknown`. Detection uses the reviewed API key, and unavailable keys, failing sampling, or an existing invalid artifact only produce a skip warning. Non-active classifications are disclosed in the sync output's `AA benchmark coverage` section with their sampled score counts, and qualified profiles that relied on a reviewed fallback chain are labelled `fallback-substituted on AA data`. Only a `retired` classification — plus the reviewed policy chain, the snapshot's raw sub-benchmark values, and the chain's own floor — can replace a null primary benchmark dimension; a missing or stale artifact keeps strict gating. A changed artifact counts as a changed AA generation and appears as an `M` target. See [`../04-subagents/BENCHMARK-ROUTING.md`](../04-subagents/BENCHMARK-ROUTING.md) for the substitution rules.

Verified native `compat.supportsReasoningEffort` is retained so fixed-effort models can only receive generic AA mappings. A validated, non-empty provider `thinkingLevelMap` is positive native capability evidence when that boolean is absent; an explicit `false` always wins, and otherwise unknown native effort capability is not treated as selectable. Sync resolves the AA snapshot root and owner-only canonical mappings through the shared AA configuration, including `PI_AA_SNAPSHOT_ROOT`. AA catalog authentication is isolated from separately constructed unauthenticated public-page requests. See [`aa/README.md`](./aa/README.md) for endpoint, streaming, schema, and transaction guarantees.
