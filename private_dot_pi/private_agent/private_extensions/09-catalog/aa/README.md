# Artificial Analysis snapshot service

This directory is the authoritative Artificial Analysis implementation. Run it directly under Node's native TypeScript support with `node agent/extensions/09-catalog/aa/cli.ts --check` (or another documented option). Modules reachable from the CLI use Node built-ins and erasable TypeScript only.

`schema.ts` is pure and shared with `04-subagents`. It strictly validates code-owned v4 artifacts and reviewed mappings. Multiple runtime aliases may repeat the same canonical thinking-level/AA UUID pair; conflicting UUIDs and generic/specific mixes remain invalid. Normal readers reject every legacy schema. Only `refreshAll` may extract identity mappings from an exact v3 manifest; it always fetches new scores and provenance.

Authenticated discovery and publication requests are limited to the canonical HTTPS free AA endpoint (`/api/v2/language/models/free`), reject redirects, stream under a byte cap, and attach `x-api-key` only after URL validation. Public model-page requests are separately constructed without authentication, manually validate every redirect hop, stream under their own cap, and parse one narrow Next/RSC `currentModel` field without attempting to decode unrelated RSC tokens. The public methodology label must come from that model payload, or—when the current Next.js page streams it separately—from the exact server-rendered `Artificial Analysis Intelligence Index v… incorporates` label. Generic HTML or RSC decoys cannot pin it. Errors and transaction metadata never contain credentials, headers, response bodies, or unrelated provider configuration.

Every writer holds an atomic directory lock from baseline validation through fetching and publication. Staging stays on the snapshot filesystem. New immutable snapshots are installed exclusively and collisions are verified by canonical digest. Readers validate only files referenced by the current manifest, so preinstalled files for the next generation and harmless crash leftovers cannot invalidate the active generation. The validated manifest is the sole publication commit point. Reviewed runtime aliases resolve to their canonical snapshot identity, but publication never rewrites the separately reviewed `canonical-mappings.json`; an update that would orphan or mismatch one of those mappings is rejected. Pre-commit failures remove newly installed snapshots. Direct CLI writes retain the immediately prior generation and recently created unreferenced files; their older unreferenced-file grace prune remains best-effort and can only produce a cleanup warning.

Interactive `/catalog sync` passes `prune: false` for every reviewed publication. Its decisive cleanup runs under the same lock only after the whole sync, including final catalog reconciliation, succeeds and at least one successful publication reports `changed: true`; a successful semantic no-op skips cleanup. That cleanup validates the secure root, models directory, manifest, and manifest digest, then removes secure generated snapshot JSON files not referenced by the final manifest. It skips unsafe or unexpected filenames with generic warnings, continues after individual deletion failures, never rolls back the manifest, and never invokes chezmoi. Artifact capture records the resolved snapshot root plus both a display path and resolved absolute target for the manifest and canonical mappings. The manifest target is the configured manifest path; the mapping target is `PI_AA_CANONICAL_MAPPINGS`, which may be outside `PI_AA_SNAPSHOT_ROOT`. The final UI computes true net disk changes from validated before/after state: metadata-content changes are `M` (manifest, then mappings), manifest-reference additions are `A models/<snapshot>`, and removed generated files are `D models/<snapshot>`. A display path is root-relative only when its target is actually inside the configured snapshot root; an external mapping is displayed as an absolute path. The net report assumes no concurrent external AA writer during interactive review.

For a nonempty change list, the UI then prints runnable POSIX groups in exact order: `chezmoi add --` with absolute M/A targets, `chezmoi forget --` with absolute D targets, and `rm -f --` with those same D targets; groups without targets are omitted. Arguments are POSIX single-quoted, including the standard `'"'"'` encoding for an embedded single quote, and no shell expansion or chezmoi source path is printed. These commands are never executed by the service. Final cleanup already deleted D files, so `rm -f` is intentionally redundant and idempotent. If any target is nonabsolute or contains C0/DEL control characters, every exact command is suppressed in favor of a generic warning that does not echo the unsafe path. `Review with: chezmoi status` remains after the commands.

Because that final cleanup can remove the prior generation, both AA readers retry exactly once only when a referenced snapshot is missing and a fresh manifest read proves its content changed. Corruption, unsafe permissions, a missing snapshot with an unchanged manifest, and every other error remain fail-closed.

The in-process service exports `discover`, `discoverCatalog`, `discoverMany`, `add`, `replaceBatch`, `refresh`, `refreshAll`, and alias-aware `replaceReviewedVariants`. `/catalog sync` uses `discoverCatalog` to fetch the authenticated canonical free catalog once, return normalized non-binding suggestions for every reviewable model, and reuse that exact response for all confirmed publications in that sync. It never fetches public pages during discovery, never maps a suggestion automatically, and uses each selected model's canonical public page only after the TUI confirms publication. The command propagates its abort signal and does not create batch files or spawn subprocesses.
