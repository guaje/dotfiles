# Artificial Analysis snapshot service

This directory is the authoritative Artificial Analysis implementation. Run it directly under Node's native TypeScript support with `node agent/extensions/09-catalog/aa/cli.ts --check` (or another documented option). Modules reachable from the CLI use Node built-ins and erasable TypeScript only.

`schema.ts` is pure and shared with `04-subagents`. It strictly validates code-owned v4 artifacts and reviewed mappings, and pins the Intelligence Index methodology (`METHODOLOGY`) plus the separately versioned public-page methodology. Multiple runtime aliases may repeat the same canonical thinking-level/AA UUID pair; conflicting UUIDs and generic/specific mixes remain invalid. Normal readers reject every legacy schema, and a methodology mismatch throws an error naming both the local pin and the upstream or on-disk version. `extractLegacyV4Mappings` is the migration bridge: a digest-verified v4 manifest pinned to a different methodology version yields its mappings to every writer (add, refresh, replace, and refresh-all alike), so the next publication republishes the complete set under the current pin; snapshots are never trusted across methodology versions, and corrupt legacy manifests still fail closed. Only `refreshAll` may additionally extract identity mappings from an exact v3 manifest; it always fetches new scores and provenance.

Authenticated discovery and publication requests are limited to the canonical HTTPS free AA endpoint (`/api/v2/language/models/free`), reject redirects, stream under a byte cap, and attach `x-api-key` only after URL validation. Public model-page requests are separately constructed without authentication, manually validate every redirect hop, stream under their own cap, and parse one narrow Next/RSC `currentModel` field without attempting to decode unrelated RSC tokens. The public methodology label must come from that model payload, or—when the current Next.js page streams it separately—from the exact server-rendered `Artificial Analysis Intelligence Index v… incorporates` label. Generic HTML or RSC decoys cannot pin it. Errors and transaction metadata never contain credentials, headers, response bodies, or unrelated provider configuration.

Every writer holds an atomic directory lock from baseline validation through fetching and publication. Staging stays on the snapshot filesystem. New immutable snapshots are installed exclusively and collisions are verified by canonical digest. Readers validate only files referenced by the current manifest, so preinstalled files for the next generation and harmless crash leftovers cannot invalidate the active generation. The validated manifest is the sole publication commit point. Reviewed runtime aliases resolve to their canonical snapshot identity, but publication never rewrites the separately reviewed `canonical-mappings.json`; an update that would orphan or mismatch one of those mappings is rejected. Pre-commit failures remove newly installed snapshots. Direct CLI writes retain the immediately prior generation and recently created unreferenced files; their older unreferenced-file grace prune remains best-effort and can only produce a cleanup warning. `/catalog sync` additionally runs `enforceScope`: the enabled `/scoped-models` list is the lifecycle authority for the asset folder, so manifest entries and `canonical-mappings.json` rows whose runtime and canonical identities are no longer enabled are dropped in one lock-serialized rewrite that never re-fetches retained snapshots (which stay byte-identical, so their content digests remain valid); entries stored under a canonical identity are retained while the scoped runtime still resolves to it. A missing, corrupt, or legacy-pinned manifest fails enforcement closed with a skip warning and leaves the artifacts untouched.

Interactive `/catalog sync` passes `prune: false` for every reviewed publication. Its decisive cleanup runs under the same lock only after the whole sync, including final catalog reconciliation, succeeds and scope enforcement, benchmark-health detection, or a successful publication reports a changed generation; a fully semantic no-op skips cleanup. That cleanup validates the secure root, models directory, manifest, and manifest digest, then removes secure generated snapshot JSON files not referenced by the final manifest. It skips unsafe or unexpected filenames with generic warnings, continues after individual deletion failures, never rolls back the manifest, and never invokes chezmoi. Artifact capture records the resolved snapshot root plus both a display path and resolved absolute target for the manifest, canonical mappings, and benchmark-health artifact. The manifest target is the configured manifest path; the mapping target is `PI_AA_CANONICAL_MAPPINGS`, which may be outside `PI_AA_SNAPSHOT_ROOT`. The final UI computes true net disk changes from validated before/after state: metadata-content changes are `M` (manifest, then mappings, then benchmark health), manifest-reference additions are `A models/<snapshot>`, and removed generated files are `D models/<snapshot>`. A display path is root-relative only when its target is actually inside the configured snapshot root; an external mapping is displayed as an absolute path. The net report assumes no concurrent external AA writer during interactive review.

For a nonempty change list, the UI then prints runnable POSIX groups in exact order: `chezmoi add --` with absolute M/A targets, `chezmoi forget --` with absolute D targets, and `rm -f --` with those same D targets; groups without targets are omitted. Arguments are POSIX single-quoted, including the standard `'"'"'` encoding for an embedded single quote, and no shell expansion or chezmoi source path is printed. Long arguments are split into short adjacent quoted fragments joined by an escaped newline; intermediate fragments start at column zero so POSIX concatenates the original path. Copy the whole group unchanged. These commands are never executed by the service, so it cannot tell whether a D target is tracked; run `chezmoi forget` only for deleted targets confirmed as managed by `chezmoi status`. Final cleanup already deleted D files, so `rm -f` is intentionally redundant and idempotent. If any target is nonabsolute or contains C0/DEL control characters, every exact command is suppressed in favor of a generic warning that does not echo the unsafe path. `Review with: chezmoi status` remains after the commands.

Because that final cleanup can remove the prior generation, both AA readers retry exactly once only when a referenced snapshot is missing and a fresh manifest read proves its content changed. Corruption, unsafe permissions, a missing snapshot with an unchanged manifest, and every other error remain fail-closed.

The in-process service exports `discover`, `discoverCatalog`, `discoverMany`, `add`, `replaceBatch`, `refresh`, `refreshAll`, and alias-aware `replaceReviewedVariants`. `/catalog sync` uses `discoverCatalog` to fetch the authenticated canonical free catalog once, return normalized non-binding suggestions for every reviewable model, and reuse that exact response for all confirmed publications in that sync. It never fetches public pages during discovery, never maps a suggestion automatically, and uses each selected model's canonical public page only after the TUI confirms publication. The command propagates its abort signal and does not create batch files or spawn subprocesses. `enforceScope` runs after the interactive review loop on every `/catalog sync` (it needs no API key and performs no network I/O); it returns the dropped `provider/model (level)` identities, and the sync reports them and treats the rewrite as a changed generation so the decisive cleanup and the exact `chezmoi forget`/`rm -f` guidance run even when nothing was published.

`detectBenchmarkHealth` tracks upstream sub-benchmark retirements so qualification can distinguish a model AA never evaluated from a benchmark AA stopped evaluating. `/catalog sync` invokes it through a wrapper that skips all work while a parsable artifact is at most seven days old; missing, corrupt, stale, or future-dated artifacts re-assess, and each re-assessment rewrites the file only when its classification digest changes. Detection uses the same reviewed API key as publication, fetches the authenticated free catalog once, keeps only dated base releases (rejecting slugs whose suffix marks a thinking, size, or quantization variant), samples up to five per 30-day window across the newest, middle, and oldest 30-day windows, and fetches each sampled model's canonical public page with the ordinary page guards and rate delay. Every monitored field is classified `active` when at least one sampled page from the newest 30-day cohort scores it, `lagging` when some sampled page scores it but none in that cohort does, `retired` when no sampled page scores it, and `unknown` when fewer than ten sampled pages were readable. The result is written as digest-verified, methodology-pinned `benchmark-health.json` (mode 0600, staged and renamed under the writer lock) only when its digest changes; an existing invalid artifact aborts detection with a skip warning instead of being overwritten by detection alone. Publication-time snapshots additionally record the raw public component values `critpt`, `gpqa`, `hle`, and `ifbench` in an optional digest-covered `subBenchmarks` field of the same v4 snapshot schema. Readers (04-subagents `loadBenchmarkHealth`) return null for anything missing, stale, future-dated, group-readable, or digest-mismatched, so absent detection output permanently preserves the strict no-substitution behavior.
